# 技能组合编排（B3）

加载时机：S4 判定需求跨多个 Skill、或 S14–S17 定目录结构时加载；只在需求确需组合时读本文件。

## 1. 何时才需要组合

单 Skill 能独立完成且产出可验收，就不组合。出现下列形态才进入编排：

| 形态 | 判据 | 典型信号 |
| --- | --- | --- |
| 串联 | 前一 Skill 的产出是后一 Skill 的输入 | 先做 A，再拿 A 的结果做 B |
| 并行 | 子任务相互独立、可同时做、最后汇总 | 三份材料分别整理，再合成一份 |
| 条件分支 | 按输入类型或场景选不同 Skill | 合同走审查，流水走对账 |

一次性任务不编排：写进一次提示词或人工做一次更快。

## 2. 三种形态的写法

**串联**：入口 Skill 步骤按执行顺序编号，每步写「调哪个成员 Skill 的哪一步、取哪个产出」；相邻两步之间必须有产出物契约，契约不成立就加转换步，不硬接；上游失败的下游动作写进下游步骤的失败分支。

**并行**：入口步骤分「分发 / 汇总」两段。分发写清每个子任务的输入与产出文件名；汇总写清合并字段与去重规则。并行子任务不共享上下文，共同前提在分发前一步落成文件；失败按子任务隔离，一个子任务失败只标该项。

**条件分支**：入口第一步写路由判据表，按可判定字段分流，不按「看起来像」。判据必须是输入里可直接读出的扩展名或字段；全不匹配时终止并给替代方案（话术见 references/rejection-scripts.md）。

| 判据 | 取值 | 走哪个 Skill |
| --- | --- | --- |
| 输入扩展名 | `[.docx]` | `[成员 Skill A]` |
| 输入扩展名 | `[.xlsx]` | `[成员 Skill B]` |
| 均不匹配 | — | 终止，给替代方案 |

## 3. 接口约定（四项）

### 3.1 产出物契约

每个交接点写一张契约表，字段名、单位、日期格式在整条链上统一；不统一的字段在交接前转换。

| 字段 | 填写内容 |
| --- | --- |
| 产出文件名 | `[文件名.扩展名]` |
| 必含字段 | `[字段 1]`、`[字段 2]` |
| 格式 | Markdown 表 / JSON / `[格式名]` |
| 验收判定 | `[行数 / 字段齐全 / 数值一致]` |

### 3.2 加载顺序

入口 Skill 正文只写步骤与路由，不复制成员方法；每步只加载当步需要的成员 references。成员 Skill 保持原样，不为编排改动。

### 3.3 上下文预算

入口主文件 ≤300 行；成员方法细节留在各自包内。一次只加载当步所需文件，禁止把多个成员 Skill 全文拼进入口包。

### 3.4 失败传递

| 上游情形 | 下游动作 | 记录什么 |
| --- | --- | --- |
| 产出文件缺失 | 停在本步，回上游步骤补 | 缺失文件名与退回步号 |
| 字段不齐或单位不一致 | 先转换；转换不了标「待确认」 | 差异字段与处置结论 |
| 上游判定不通过 | 终止整条链，不进入下游 | 失败步号与判定依据 |

## 4. 组合说明写在哪

只在入口 Skill 的 `references/` 写一份编排说明（照本文件结构写），写清五项：形态、成员清单、交接契约、加载顺序、失败传递。成员 Skill 包内不写编排说明，不互相添加引用，同一信息只留一处。入口 Skill 目录：`SKILL.md` + `references/` 下一份编排说明；没有确定性脚本时不建 `scripts/`。

## 5. 回归用例与测试资产

用例放包外 `tests/`（与技能包平级），入口 Skill 包内不留用例与报告。至少三类：正常链、上游失败、路由未命中；记录字段：用例号、形态、输入、期望产出、失败注入、结论。改任何交接契约后，三类用例整体重跑。

## 6. 边界：编排是不是一个独立 Skill

S4 四项准入之外，另加两条判据：

| 判据 | 命中 | 未命中 |
| --- | --- | --- |
| 契约稳定 | 交接字段固定、可版本化，做成独立入口 Skill | 字段每次变，写成一次性提示词 |
| 成员可独立复用 | 每个成员 Skill 单独也有触发场景 | 成员只服务这一条链，合进一个 Skill |

两条都未命中时，把编排降为现有 Skill 的一步，或人工按顺序执行，不为「组合」单独建包。

## 7. 两个例子

### 7.1 串联：合同审查 → 风险摘要

1. 入口 S1 调 `[合同审查 Skill]`，产出 `[风险条款清单.md]`，字段：条款号、风险等级、修改动作。
2. 入口 S2 以清单为输入，调 `[摘要生成 Skill]`，产出 `[风险摘要.docx]`，字段：结论、三项高风险条款、处置动作。
3. 交接契约：S1 输出必须含条款号；缺失时 S2 失败分支退回 S1 补条款定位。

### 7.2 并行：竞品资料采集

1. 入口 S1 分发三个子任务：从 `[竞品规格书.pdf]` 提功能表、从 `[定价页.html]` 提价格、从 `[用户评价.csv]` 提取高频抱怨，各产出一份 Markdown。
2. 入口 S2 汇总：按「功能 / 价格 / 抱怨」三栏合并，重复条目按竞品名去重，缺失子项标「未采到」。
3. 失败传递：任一子任务失败只标该子项，不阻塞汇总；三份全失败时终止并给替代方案。

## 8. 禁止项

1. 把多职责塞进一个 SKILL.md，一个包内写多套互不衔接的方法。
2. 无契约拼接：直接拿上游产出当输入，不写文件名、字段与验收判定。
3. 循环依赖：A 等 B 的产出、B 又等 A 的产出。
4. 编排说明散落在各成员 Skill 包内，同一信息多处维护。
5. 把组合用例与报告放进入口 Skill 包内。
6. 入口包加载成员 Skill 全文，挤占上下文预算。
