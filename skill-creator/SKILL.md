# skill-creator 流水线

本流水线接收一句用户需求，按六环节执行，产出可部署 Skill 包与四块交付物。人类只在环节二末尾（需求确认）与环节六末尾（交付确认）介入。环节间不循环、不回跳，仅按失败分支退回指定环节；四块交付物给齐且人类确认接收，流水线终止。

## 执行约束

- C1 被测对象在外部：输入是用户需求，输出是对应 Skill 包。禁止对产出物做二次分析，禁止讨论流水线自身算不算 Skill。
- C2 停止条件写死：目录树、SKILL.md 全文或路径、自检结论、待确认项四块给齐且人类确认接收即终止。禁止对本次产出再跑一遍流水线，禁止对自检结论再做自检，禁止对校验脚本写校验脚本。
- C3 语体去元化：全文用输入/执行/产出/退回语气。禁词：元技能、自指、递归、套娃、技能之技能、元层面、自举、反身。
- C4 验证边界封顶：只验产出物结构——文件、行数、路径、占位符、空目录、测试目录、权限、敏感路径、密钥。验完即停。
- C5 测试资产外置：测试说法、报告、回归用例、诊断夹具一律放包外 tests/；包内只留可运行脚本与方法文档。

## 输入与输出

- 输入：用户一句话需求。
- 输出：可部署 Skill 包 + 四块交付物（目录树、SKILL.md 全文或路径、自检结论、待确认项）。
- 人类节点：环节二末尾需求确认、环节六末尾交付确认；其余环节自主执行。

## 环节一：准入判定

- 输入：用户一句话需求。
- 动作：执行四项核对，逐项写「命中/未命中 + 依据」。判定标准：复用性=同类任务预期 ≥3 次；非显然性=含模型推不出的规则；可判定产出=有可验收交付物；步骤化=≥3 个有序且依赖的步骤。
- 产出：四项判定表，四项各一行。
- 判定：命中 ≥3 进入环节二；命中 ≤2 进入失败分支。
- 失败分支：输出终止结论「该需求不适宜做成 Skill」，按 references/rejection-scripts.md 选定一种替代方案（一段提示词、一个脚本、一个模板、人工做一次），逐项写理由；流水线终止。

## 环节二：需求采集

- 输入：环节一通过的需求。
- 动作：执行两轮采集，字段定义见 references/intake-fields.md，空白模板见 assets/intake-card.md。第一轮只采集触发：会怎么开口触发（要原话）、什么任务、谁发起、多久一次，最多三问。第二轮采集交付与边界：最终交付什么（具体到文件名与字段）、明确不做什么、哪些相邻需求不误触发，最多三问。缺口按字段逐个补问，已填字段不重复问。
- 产出：八字段需求卡（服务对象、真实场景、触发原话、目标产出、关键约束、不做什么、相邻易混淆需求、待确认项）；推断项标「推断」。
- 判定：八字段填满→交人类确认。确认通过进入环节三；确认不通过→按人类意见修改八字段后重新交确认。
- 失败分支：人类连续两次不确认→判定需求不清楚，输出「先用一段提示词试一次」及提示词骨架；流水线终止。退回原因记录为「需求卡两次未确认」。

## 环节三：触发描述生成

- 输入：环节二确认的需求卡。
- 动作：按三段式生成 description（做什么 + 什么时候用 + 不覆盖什么），执行硬关六项核对与三说法测试；规则定义见 references/description-spec.md。
- 产出：description 草稿、硬关核对表、三说法测试记录。
- 判定：硬关六项全过（第三人称、≤1024 字符、≥3 条「」原话、≥1 个可识别对象、写清不做什么、七个禁词零出现）且三说法全中→进入环节四；任一不过进入失败分支。
- 失败分支：硬关不过→按不过项修改后重跑硬关核对；三说法任一不中→补该类原话后重跑三条。同一问题连续两次不过→退回环节二补采集，退回原因写入测试记录。

## 环节四：结构决策

- 输入：环节三定稿的 description。
- 动作：先输出默认最小集（只有 SKILL.md），给行数预算（目标 300 行、上限 500 行）；再执行三问：有大量细节用到才读？有确定性操作要可复现？有要复制填充的模板？每答「是」写一句「该内容不能放主文件的理由」。判定标准与输出格式见 references/structure-rules.md。
- 产出：目录树 + 每个非默认目录一行理由 + 行数预算。
- 判定：三项产出齐全且每个非默认目录理由合格→进入环节五；否则进入失败分支。
- 失败分支：某目录写不出合格理由→从目录树删除该目录，回最小集重新执行三问。

## 环节五：正文生成

- 输入：环节四的目录树。
- 动作：按六段骨架生成正文（目标、前置、步骤、输出示例、禁止项、常见错误），模板见 assets/skill-template.md；每步写四要素（输入、动词开头的动作、产出、失败分支），编号连续；按 references/body-spec.md 的对照表把模糊词替换为可判定条件句；清空占位符；统一语体。
- 产出：六段正文，主文件行数在预算内。
- 判定：六段齐全、每步四要素齐全、模糊词零残留、占位符零残留、行数在预算内→进入环节六；否则进入失败分支。
- 失败分支：行数超预算→把最易超的一段外置到 references/ 并在主文件写加载指令，重新核对行数。某步写不出失败分支→退回环节二确认该步要做什么，退回原因写入需求卡「待确认项」。

## 环节六：校验与交付

- 输入：环节五的正文与包目录。
- 动作：按顺序执行三件事。(1) 运行 `python scripts/validate_structure.py <包目录>`，核对 11 项检查，0 FAIL 才继续。(2) 运行 `python scripts/check_triggers.py --skill <包目录> --phrasings <说法清单>`，三说法全中才继续；若备了负样本清单，加 `--negatives <负样本清单>` 一起跑，负样本无误触发才继续。(3) 按 references/self-check.md 逐项判三态（通过/待确认/不通过）。三件事完成后整理四块交付物。
- 产出：校验结果、人工清单三态、四块交付物（目录树、SKILL.md 全文或路径、自检结论、待确认项）。
- 判定：0 FAIL 且人工清单无「不通过」→交人类交付确认。人类确认接收→流水线终止；人类拒绝→按拒绝意见修复后从环节六起点重跑。
- 失败分支：结构校验 FAIL→按 references/rollback-table.md 定位修复，修完从环节六起点重跑，不许只修人工项；内容校验 P007 报槽位残留→按 references/body-spec.md 第 4.1 节区分真残留与合法引用；触发测试不过→回环节三；负样本误触发→回环节三补排除场景；人工清单有「不通过」→修复后重跑脚本与清单；退回原因与修复记录写入自检结论。

## 不覆盖

本流水线主流程只负责从需求到可部署 Skill 包的生成；上述扩展功能按需加载，不进入主流程。不覆盖平台 UI 操作与账号授权、复杂工程集成；这些需求做成独立 Skill，与本流水线平级。

## 禁止项

1. 跳过环节一准入判定直接写包。
2. 需求卡未经人类确认就写 description。
3. description 少于三条「」用户原话触发语。
4. 主文件超过行数预算且未外置说明。
5. 引用路径不真实存在。
6. 使用绝对路径或从工作区根算起的路径。
7. 技能包内放测试资产。
8. 留空目录或占位文件。
9. 对产出物做二次分析，讨论本流水线自身算不算 Skill。
10. 交付时只说「已完成」，不给四块交付物。

## 停止条件

四块交付物齐全且人类确认接收即终止。禁止对本次产出再跑一遍流水线，禁止对自检结论再做自检，禁止对校验脚本写校验脚本，禁止对产出物再做产出。
