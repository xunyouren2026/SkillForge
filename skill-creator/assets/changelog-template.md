# CHANGELOG 模板（S27–S28 加载）

加载时机：S27 给目录树与版本号、S28 给自检结论时加载；生成 `CHANGELOG.md` 放技能包根目录，新版本另起一节，只追加不覆写。

## 1 条目骨架

```markdown
## [版本号] ISO 日期
### 改了什么
### 影响哪些步骤
### 需要重跑哪些检查
```

## 2 填好的示例条目

```markdown
## [2.0.0] 2026-11-15
### 改了什么
- `SKILL.md` 的 description：术语型触发语补 2 条（「一阶线性方程用积分因子怎么列式」「常微分方程的积分因子」）；排除场景补「不做数值仿真」。
- `SKILL.md` 的 S3：补失败分支「方程不是一阶线性时，回 S2 重新判定」。

### 影响哪些步骤
- S10–S13：description、硬关、三种说法测试、定稿。
- S20：正文步骤与失败分支。

### 需要重跑哪些检查
- S23 结构校验：`python scripts/validate_structure.py [技能目录]`，0 FAIL。
- 触发测试：`python scripts/check_triggers.py --skill [技能目录] --phrasings [说法清单]`，三种说法 3/3 命中。
- S24 人工清单：`references/self-check.md` 12 项逐条重判三态，每项留证据。
```

## 3 填写规则

| 栏 | 规则 |
| --- | --- |
| 版本号 | 三段式 `主.次.修订`，不带 `v` 前缀。触发面变化升主版本；步骤与目录变化升次版本；文字修正升修订号；同时涉及多类按就高原则。规则见 `references/versioning.md` |
| 日期 | ISO 格式 `YYYY-MM-DD`。同一天多次改动合并为一条，版本号取最高位 |
| 改了什么 | 逐条写文件、段落、改前与改后，涉及多个文件时逐文件列出；不写「优化了 description」这类概括句 |
| 影响哪些步骤 | 填 S 编号：描述改动写 S10–S13，结构改动写 S14–S17，正文改动写 S18–S22，自检与交付固定写 S23–S30 |
| 需要重跑哪些检查 | 从 S23 结构校验、`scripts/check_triggers.py`、S24 人工清单三项里按影响面勾选，逐条写命令与验收值；任一不过不交付 |

「改动原因」与「回归用例」并入「改了什么」：根因写具体触发条件或失败现象，回归用例取自需求卡原话并逐字记录。首次交付写 `[1.0.0]` 与第一条，version 字段同步升位。
