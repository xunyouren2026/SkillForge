# 需求卡模板

加载时机：环节一「准入判定」起卡、环节二「需求采集」补卡时加载；按字段序号取用，读完即填，不整包读入。

## 1 八字段空白模板

| # | 字段 | 填写内容 | 判定 |
| --- | --- | --- | --- |
| ① | 用户原话 | [原话] | 至少 1 条；定稿前按第 2 节补到三类各 ≥3 条 |
| ② | 真实场景 | [谁发起 / 多久一次 / 在什么对话里] | 三项齐全，能复述出一个具体场景 |
| ③ | 触发时机 | [三类说法，见第 2 节] | 三类各 ≥3 条，合计 ≥9 条 |
| ④ | 目标产出 | [文件名 + 文件类型 + 必含字段] | 文件名与字段可验收，不写「一份报告」 |
| ⑤ | 关键约束 | [固定口径 / 顺序 / 格式 / 不可覆盖项] | 每条可判定，≥3 条 |
| ⑥ | 不做什么 | [三类排除，见第 3 节] | 三类各 ≥1 条 |
| ⑦ | 相邻易混淆需求 | [任务 + 归属去向] | 每条写清归属判据 |
| ⑧ | 待确认项 | [推断项 + 需拍板问题 + 当前默认] | 每条含确认什么 / 不确认后果 / 当前默认 |

推断项逐条带「推断」二字，与已确认内容分栏存。字段全空退回环节一补一句话需求，不凭空编造。

## 2 触发原话三类

按类各留两行空白位；定稿前每类补到 ≥3 条，合计 ≥9 条。

```
口语型：
[原话]
[原话]

术语型：
[原话]
[原话]

无术语型：
[原话]
[原话]
```

填写规则：原话，不改写，不术语化。

| 类型 | 判据 | 不合格格式 |
| --- | --- | --- |
| 口语型 | 日常对话原句，可含口头语、省略主语 | 术语化改写句 |
| 术语型 | 含领域名词或文件类型 | 无领域词的口语句 |
| 无术语型 | 不带技能词与领域词 | 设计者口吻的概括句 |

任一类不足 3 条 → 回环节二补问，不编造原话。

## 3 不做什么三类

| 类别 | 填写行 | 判定 |
| --- | --- | --- |
| 能力不做 | [能力项 + 替代路径] | 写清本技能做不到什么，指向人工或其他技能 |
| 场景不做 | [不出手的条件] | 条件可判定，不写「不适用于其他场景」 |
| 判断不做 | [必须由人拍板的事项] | 本技能只给判据，不替人决定 |

三类各至少一行，缺类回环节二补问。

## 4 填写规则

| 规则 | 判定 |
| --- | --- |
| 原话不改写 | 触发原话与「不做什么」保留原话措辞；概括后不可核对，判不合格 |
| 推断标注 | 非用户明说内容标「推断」，并入待确认项 |
| 确认前不写 description | 需求卡整体确认通过前不写 description；不通过按意见改后重确认 |
| 只问缺项 | 已填字段不再问；缺的字段按环节二问法补 |
