# 示例 5｜周报生成器：从一句话需求到成品 Skill

本目录是 `skill-creator` 的第五个成品示例，领域为日常办公协作。入口是 `SKILL.md`；本文件说明这条需求经过 skill-creator 的哪些步骤，以及「一句话需求」如何逐段落成成品形态。

## 1. 一句话需求

> 「周五了，周报还没写，帮我把这周干的事整理成周报」

## 2. 演示 skill-creator 哪几步

| skill-creator 步骤 | 本范例的落点 | 可核对内容 |
| --- | --- | --- |
| S1 分流 | 判为新建线 | 每周重复交、字段固定、产出可验收 |
| S2–S3 收集与需求卡 | 八字段需求卡 | 见第 3 节 |
| S4–S5 准入 | 四项核对命中 4/4 | 复用性、非显然性、可判定产出、步骤化 |
| S6–S9 边界与访谈 | 交付字段与排除场景 | 月报、季报、OKR 复盘不归本技能 |
| S10–S13 description | 三段式 description | 4 条「」原话 + `weekly-report.md` 对象 + 排除句 |
| S14–S17 目录 | 最小集：技能本体只有 `SKILL.md` | 无 references/、无 scripts/、无 assets/ |
| S18–S22 正文 | 六段骨架 + 步骤四要素 | 见 `SKILL.md` 全文，步骤编号 S1–S6 |
| S23–S26 自检 | 结构校验、人工清单、待确认项标注 | 测试资产按 C5 放包外 `tests/` |
| S27–S30 交付 | 目录树、主文件、自检结论、待确认项 | 本目录即交付形态 |

## 3. 需求卡摘要（S3 产出）

```
用户原话：       「周五了，周报还没写，帮我把这周干的事整理成周报」
真实场景：       研发小组，每周五下班前交周报，此前每次重写格式
触发时机：       口语「帮我写个周报」/ 术语「把本周进展汇总成周报」/ 无术语「这周干的事整理一下」
目标产出：       weekly-report.md；七个固定字段，逐条带来源
关键约束：       只登记有来源的事实；缺数据写「缺数据」；字段固定
不做什么：       「不覆盖月报、季报、绩效自评、OKR 复盘、项目复盘与工时统计」
相邻易混淆需求： 「月度汇报」「项目复盘」→ 归属其他技能
待确认项：       「推断」：默认周期为最近一个完整自然周
```

## 4. 一句话需求 → 成品映射

| 需求侧的说法 | 中间决策 | 成品里的落点 |
| --- | --- | --- |
| 「周五了，周报还没写」 | S1 分流为新建线；S4 四项核对 4/4 | `SKILL.md` 落地 |
| 「把本周进展汇总成周报」 | S7 收原话；S10–S13 写 description | 4 条「」触发语 + 排除场景 |
| 「按模块分，别每次换格式」 | S8 定交付物；S19–S21 定字段与示例 | 七个固定字段 + 输出示例 |
| 「每周五都要交」 | S4 复用性；S14 取最小集 | 只有 `SKILL.md`，无额外目录 |
| 「写不出的事实别编」 | S21 禁止项；S23–S26 自检 | 禁止项 6 条 + 常见错误 5 行 |

## 5. 边界与待确认

- 本目录是 skill-creator 的产出物，不属于其运行文件；触发测试与结构校验记录按 C5 放在包外 `tests/`。
- 平台真实召回未测，按 S26 记为待确认项：上线前在目标平台补测三类触发说法。
- 跨时区团队的周期口径未定，默认按本地自然周处理。
