# 周报生成器（weekly-report-generator）

## 一、目标

把一周零散的工作项整理成一份字段固定、逐条可核对的周报，落盘为 `weekly-report.md`：周期范围 → 模块分组 → 本周完成 → 进行中 → 风险与阻塞 → 下周计划 → 待确认项。

1. **事实与计划分开**：工作项只登记有来源的事实；计划从进行中与阻塞项推导，不提前写成完成。
2. **字段固定**：七个字段一个不少；缺数据写「缺数据」并列入待确认项，不留空段。
3. **逐条可核对**：每条工作项带来源（提交哈希、工单号或会议纪要行号），自检时逐条核对。

### 适用范围与边界

- **覆盖**：个人或小组的周报，周期为周一至周五一个自然周；输入为工作项清单、git 提交记录、工单列表、会议纪要。
- **不覆盖**：月报、季报、绩效自评、OKR 复盘、项目复盘、工时统计。
- **待确认**：跨时区团队的周期口径（本地周或 UTC 周）在交付时请用户确认。

## 二、前置

| 项 | 说明 | 缺失时的处理 |
| --- | --- | --- |
| 周期范围 | 起止日期，默认最近一个完整自然周（周一至周五） | 未指定 → 取默认值，文件首行标注「推断」 |
| 工作项来源 | 工作项清单、git 提交、工单导出、会议纪要，至少一种 | 全缺 → 列待确认项并停止收集，不虚构工作项 |
| 模块口径 | 模块名清单，或按业务线分组 | 未给 → 按工作项自带模块字段归并，空值归「未分类」 |
| 状态口径 | 完成 / 进行中 / 阻塞 | 未给 → 用三种默认状态，不另造状态名 |

字段固定为七个：周期、模块、本周完成、进行中、风险与阻塞、下周计划、待确认项。列表类字段无内容写「无」；来源缺失写「缺数据」，且必须进入待确认项。

资源索引：

| 资源 | 加载时机 | 说明 |
| --- | --- | --- |
| `SKILL.md` | 始终 | 唯一必需文件；可读写 Markdown 的编辑器即可，无脚本依赖 |
| `weekly-report.md` | S4 生成、S5 自检 | 产出文件，开工前不存在 |

## 三、步骤

### S1 确定周期与来源

- 输入：用户给的日期范围与工作项来源。
- 动作：算出周期起止（默认最近完整自然周，周一至周五）；列出本次可用来源；日期未指定时写明采用的默认值。
- 产出：一行周期结论 + 来源清单。
- 失败分支：来源全缺 → 列待确认项并停在收集阶段，不虚构工作项。

### S2 收集本周工作项

- 输入：周期范围 + 来源清单。
- 动作：逐条提取工作项，每条填五列——日期（`YYYY-MM-DD`）、事项（动词开头，≤20 字）、模块、状态（完成 / 进行中 / 阻塞）、来源（提交哈希 / 工单号 / 纪要行号）；同一事项有多个来源只登一条，来源处并列写全。
- 产出：工作项条目表，按日期升序。
- 失败分支：状态判不了 → 标「待确认」，不默认填「完成」。

### S3 按模块归类

- 输入：工作项条目表。
- 动作：按模块字段归并；模块为空的条目归入「未分类」并单列；统计每模块的完成数、进行中数、阻塞数。
- 产出：模块分组表（模块名 + 三类计数 + 对应条目行号）。
- 失败分支：一条事项同属两个模块 → 取主模块，另一模块在备注写「共享」，计数只记一次。

### S4 生成周报

- 输入：模块分组表 + 工作项条目表。
- 动作：按固定七字段写入 `weekly-report.md`；下周计划只从进行中与阻塞项推导；推断内容逐条标「推断」。
- 产出：`weekly-report.md`。
- 失败分支：某字段没有数据 → 写「无」或「缺数据」，后者同时列入待确认项，不留空、不编造。

### S5 自检

- 输入：`weekly-report.md`。
- 动作：逐项核对六条——周期与 S1 结论一致；七字段齐全；每条工作项带来源；模块计数与条目数一致；「缺数据」全部进入待确认项；全文无空字段。
- 产出：六项自检记录（通过 / 不通过 + 依据）。
- 失败分支：任一项不通过 → 回对应步骤重做，不带不通过项交付。

### S6 交付

- 输入：自检通过的周报。
- 动作：给出文件路径、周期范围、模块数、工作项数、待确认项清单。
- 产出：交付说明。
- 失败分支：待确认项未列全 → 回 S2 或 S4 补齐，交付说明不省略该块。

## 四、输出示例（最小交付形态）

S2 条目表示例（节选三行）：

| 日期 | 事项 | 模块 | 状态 | 来源 |
| --- | --- | --- | --- | --- |
| 2025-11-10 | 修复导出报错 | 数据导出 | 完成 | commit 3f9c2a1 |
| 2025-11-12 | 新增导出队列重试 | 数据导出 | 完成 | 工单 T-1042 |
| 2025-11-14 | 导出日志分级 | 数据导出 | 进行中 | commit a5d9e02 |

输出文件：`weekly-report.md`

```
# 周报 2025-11-10 ~ 2025-11-14

周期：2025-11-10（周一）至 2025-11-14（周五），共 5 个工作日。

## 模块：数据导出
- 本周完成：修复导出报错（2025-11-10，commit 3f9c2a1）；新增导出队列重试（2025-11-12，工单 T-1042）
- 进行中：导出日志分级（2025-11-14，约完成 60%，commit a5d9e02）
- 风险与阻塞：导出压测环境排队，等待运维放行（工单 T-1051）

## 模块：未分类
- 本周完成：无
- 进行中：季度需求评审纪要整理（2025-11-11，会议纪要第 12–18 行）
- 风险与阻塞：评审结论待产品确认（待确认项 1）

## 下周计划
1. 导出日志分级收尾（来源：进行中）
2. 压测环境放行后补压测（来源：风险与阻塞）

## 待确认项
1. 季度需求评审结论是否按当前版本执行——确认后更新「未分类」模块。
2. 导出压测环境放行时间——确认后补压测结论。
```

验收条件：`weekly-report.md` 七字段齐全；每条工作项带来源；模块计数与条目数一致；无空字段；待确认项与「缺数据」一一对应。

## 五、禁止项

1. 编造没有来源的工作项，或把「进行中」默认写成「完成」。
2. 漏写来源（提交哈希、工单号、纪要行号）。
3. 用「无」掩盖来源缺失；来源缺失写「缺数据」并列入待确认项。
4. 把月报、季报、绩效自评、项目复盘的内容塞进周报。
5. 在「下周计划」里新增 S2 未登记的工作项。
6. 周期默认值不标注「推断」，或留空字段而不写「无」「缺数据」。

## 六、常见错误

| 症状 | 根因 | 最小修复 |
| --- | --- | --- |
| 周报条目比提交记录多 | 把计划事项当完成项登记 | 回 S2 只登记有来源的事实，计划移入下周计划 |
| 某模块完成数对不上 | 同一事项跨模块重复计数 | 回 S3 取主模块、备注写「共享」，计数只记一次 |
| 工作项没有来源 | 凭记忆补写 | 回 S2 取提交哈希、工单号或纪要行号，取不到写「缺数据」 |
| 字段留空或整段缺失 | 缺数据直接跳过 | 回 S4 补「无」或「缺数据」，并补入待确认项 |
| 周期范围写错 | 默认值与用户要求混淆 | 回 S1 重算，文件首行标注采用口径 |
