# 示例 2｜数学领域成品 Skill：线性代数证明核验

本目录是 `skill-creator` 的第二个成品示例，展示「**非显然性**」判据的典型来源：模型容易直接调用谱定理去证谱定理（循环论证），需要一套强制的前提核查 + 反例检索流程。

## 1. 输入（用户原话）

> 「证明题老是要么漏条件、要么拿结论当理由，能不能帮我固定一套查前提的流程」

## 2. S0　该不该做成 Skill

| 判据 | 判定 | 依据 |
| --- | --- | --- |
| 复用性 | ✅ | 每次证明题、每次审稿都会重复 |
| 非显然性 | ✅ | 「调用定理前逐条核前提」「主动检索条件削弱后的反例」「避免循环论证」不是模型默认行为 |
| 可判定产出 | ✅ | `proof.md` 六段结构，S1/S2/S4 均可机械验收 |
| 步骤化 | ✅ | S0→S5，S1 核查表是 S3 构造证明的输入 |

命中 4/4 → 继续。

## 3. S1　需求卡（8 字段）

```
用户原话：        「证明题老是要么漏条件、要么拿结论当理由，能不能帮我固定一套查前提的流程」
真实场景：        数学系高年级 / 助教，批改证明作业与准备讨论课
触发时机：        口语「帮我证一下这个线性代数的命题」/ 术语「谱定理能不能用」
                 / 无术语「这个证明前提够不够」
目标产出：        proof.md；必含 命题重述、前提核查表、逐步证明、反例检索、降维验证、结论
关键约束：        前提逐条核查；每步标注依据；必要与充分分开；禁止循环论证
不做什么：        「不做数值计算，也不搞形式化验证」
相邻易混淆需求：  「算矩阵特征值」「实分析证明」→ 归属其他技能
待确认项：        「推断」：默认基域 ℝ；是否允许调用 Jordan 型 → 交付时确认
```

## 4. S3　目录设计

```
linear-algebra-proof-assistant/
├── SKILL.md
└── references/
    ├── theorem-preconditions.md   # 定理前提表，仅 S1 加载
    └── counterexamples.md        # 反例库，仅 S2 加载
```

- 定理前提表与反例库是**稳定领域知识、仅部分步骤用得上** → `references/`
- 本技能产出是文字证明，无需 `scripts/`（没有确定性重复计算），也无需 `assets/`（无待复制模板）
- **不建 `tests/`**：说法与报告位于工作区顶层 `tests/`

> 设计要点：目录不是越全越好。`references/` 两件、`scripts/` 零件，是本示例经过判断后的最小充分集。

## 5. S4　正文与输出示例

正文按六段骨架，见 `SKILL.md` 全文。输出示例给出命题「实对称矩阵可正交对角化」的完整证明：

- 为避免循环论证，**不直接调用谱定理**，改走 Rayleigh 商极值原理 + 正交补归纳；
- S1 前提核查表标记「正交补不变性 ⏳ 待证」，在 S3 第 3 步兑现；
- S2 给出 C1（`[[1,1],[0,1]]` 不可对角化）与 C2（可对角化但不对称），得出「充分非必要」；
- S4 用 `n=1`、`n=2` 的 `[[2,1],[1,2]]` 及退化情形 `A=λI` 三组验证。
