# 示例 1｜从模糊需求到完整 Skill：经典力学题解

本目录是 `skill-creator` 的**成品示例**，展示「一句模糊需求」经过 S0–S5 后的落地形态。领域：物理学。

## 1. 输入（用户原话）

> 「每次做力学习题都要重新想一遍怎么受力分析，能不能固定一套流程」

## 2. S0　该不该做成 Skill

| 判据 | 判定 | 依据 |
| --- | --- | --- |
| 复用性 | ✅ | 助教每周批改约 20 份作业，同类题反复出现 |
| 非显然性 | ✅ | 「摩擦方向先设无摩擦判趋势」「符号先于数值」不是模型默认行为 |
| 可判定产出 | ✅ | `solution.md`，六段结构 + 四项校验可机械验收 |
| 步骤化 | ✅ | S0→S5 共 6 步，S1 受力图是 S2 方程组的输入 |

命中 4/4 → 继续。

## 3. S1　需求卡（8 字段）

```
用户原话：        「每次做力学习题都要重新想一遍怎么受力分析，能不能固定一套流程」
真实场景：        本科助教，每周批 20 份作业，学生在群里贴题目图片
触发时机：        口语「帮我解这道力学题」/ 术语「做个受力分析」/ 无术语「又卡在摩擦力方向了」
目标产出：        solution.md；必含 受力图说明、方程组、符号解、量纲检查、带单位数值结果、结论
关键约束：        SI 单位；符号先于数值；静摩擦方向必须显式判定；有效数字按题给精度
不做什么：        「不涉及量子、相对论，也不做数值仿真」
相邻易混淆需求：  「拟合实验数据」「写实验报告」→ 归属其他技能
待确认项：        「推断」：是否需支持刚体转动 → 交付时请用户拍板
```

## 4. S2　description

```
把经典力学习题转成可复核的求解链路，产出 solution.md（受力图说明、方程组、
量纲检查、带单位的数值结果）。当出现「帮我解这道力学题」「做个受力分析」
「又卡在摩擦力方向了」「斜面弹簧怎么列方程」「每次都要重新想一遍受力分析」，
或用户提供含质点、斜面约束、摩擦、弹簧、圆周运动、守恒律的力学题目时使用。
不适用于量子力学、相对论、连续介质、实验数据拟合与数值仿真。
```

三段式齐全；5 条「」触发语覆盖口语 / 术语 / 无术语三类；可识别对象为 `solution.md`、物理量术语；排除场景明确。

## 5. S3　目录设计

```
classical-mechanics-solver/
├── SKILL.md                       # 主文件，只放路由与关键约束
├── references/
│   ├── equation-map.md            # 题型→方程选择表，仅 S2 加载
│   └── checks.md                  # 量纲 / 极限清单，仅 S4 加载
└── scripts/
    └── dimensional_check.py      # 确定性量纲校验，执行不读入
```

- 方程选择表与检查清单**只有部分步骤用得上** → `references/`
- 量纲校验每次都要重复写同一段计算且要求确定性 → `scripts/`
- 无 `assets/`（产出是文字解答，不需要被复制的模板）
- **无测试目录**：触发说法与报告位于工作区顶层 `tests/`，与本技能包分开

## 6. S4–S5　正文与自检

正文按「目标 → 前置 → 步骤 → 输出示例 → 禁止项 → 常见错误」六段，见 `SKILL.md` 全文（含一道完整可复核的斜面–弹簧数值题）。

| 自检 | 结果 |
| --- | --- |
| 结构校验 `validate_structure.py` | 见 `tests/validation-report.md` |
| 触发测试 `check_triggers.py` | 见 `tests/trigger-test-report.md` |
| 人工 12 项清单 | 通过；待确认 1 项（刚体转动是否纳入） |
