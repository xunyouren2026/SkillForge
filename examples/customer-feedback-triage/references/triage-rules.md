# 客户反馈归类规则（仅 S2–S4 加载）

本文件在 S2 判定类型前加载；S3 用第 2 节优先级矩阵，S4 用第 3 节责任组映射；其他步骤不读入。

## 1 六类判据

| 类型 | 判据（命中即归） | 原文高频词 |
| --- | --- | --- |
| 功能缺陷 | 声称已有功能未按预期工作，且可复现或已有多人反馈 | 「不能用」「报错」「付款成功但显示待支付」「数据没了」 |
| 体验问题 | 功能可用但操作成本高、路径长、提示易误解 | 「找不到」「要转好几秒」「步骤太多」「提示看不懂」 |
| 功能请求 | 要求新增能力或扩展已有能力 | 「希望支持」「能不能加」「要是有…就好了」 |
| 咨询求助 | 询问用法、规则、入口，不涉及故障 | 「怎么设置」「在哪开通」「这个是什么意思」 |
| 计费争议 | 涉及扣款、退款、发票、套餐计费口径 | 「扣了两次」「多扣钱」「退款没到账」「发票开错」 |
| 无效信息 | 广告、测试提交、与产品无关的内容 | 推广链接、重复测试内容、无关闲聊 |

## 2 优先级矩阵

| 影响面 \ 严重度 | 阻断（流程走不通） | 受限（能走但代价大） | 轻微（可绕开） |
| --- | --- | --- | --- |
| 全员或多人群 | P0 | P1 | P2 |
| 单个团队或单渠道多人 | P1 | P2 | P3 |
| 单人单次 | P2 | P3 | P3 |

P0 与 P1 必须写触发条件；P0 当日升级，P1 三日内排期，P2 与 P3 进常规评审。

## 3 责任组映射

| 类型 | 默认责任组 |
| --- | --- |
| 功能缺陷 | 对应模块研发组 |
| 体验问题 | 客户端组或交互组 |
| 功能请求 | 产品组 |
| 咨询求助 | 客服组 |
| 计费争议 | 财务组 + 计费研发组 |
| 无效信息 | 客服组记录后忽略 |

## 4 无法归类处置
- 两个候选类型都成立 → 记「无法归类」，备注写候选与理由，不取其一。
- 信息不足以判类型 → 建议动作固定为「补问目标后重新归类」。
- 同一反馈跨两类且都严重 → 按较严重类型归，备注保留次要类型。
