# 示例 4｜客户反馈归类：从一句话需求到完整 Skill

本目录是 `skill-creator` 的成品示例，演示一句模糊需求经 S1–S26 后形成的完整技能包。领域：客户成功与产品运营。

## 1 一句话需求

> 「客户群里天天有人提意见，能不能把反馈分一下类，先处理要紧的」

## 2 演示了 skill-creator 哪些步骤

| skill-creator 步骤 | 本范例对应动作 | 产物 |
| --- | --- | --- |
| S1–S3 准备 | 分流为新建线；建八字段需求卡（触发原话 5 条、不做什么 3 项） | 需求卡（见第 3 节映射） |
| S4–S5 准入 | 四项共命中 4 项：复用性写每周一次、非显然写六类判据、可判定产出写 feedback-triage.md、步骤写 S1–S6 有依赖 | 准入结论 |
| S10–S13 描述 | 三段式；5 条「」原话覆盖口语、术语、无术语；末句写排除场景 | `SKILL.md` frontmatter |
| S14–S17 结构 | 最小集起步，只增 `references/triage-rules.md`，理由为仅在 S2–S4 用到 | 目录树（见第 4 节） |
| S18–S22 正文 | 六段骨架；每步四要素；清理模糊词与占位符 | `SKILL.md` 全文 |
| S23–S26 自检 | 结构校验 11 项 0 FAIL；占位符 0；引用路径存在；人工清单留 1 条待确认 | 自检结论（测试与报告在包外 tests/） |

## 3 一句话需求 → 成品映射

| 需求里的哪句话 | 落成什么 | 成品位置 |
| --- | --- | --- |
| 「客户群里天天有人提意见」 | 来源渠道与触发场景；5 条「」原话 | description；S1 |
| 「把反馈分一下类」 | 六类判据 + 无法归类处置 | `references/triage-rules.md`；S2 |
| 「先处理要紧的」 | 影响面×严重度矩阵、P0–P3、触发条件 | `references/triage-rules.md`；S3 |
| 「能不能…」 | 复用性（每周一次，已连续 12 周）与准入结论 | 第 2 节 |
| 交付物形态 | `feedback-triage.md` 九字段明细表 + 统计段 + 待确认段 | `SKILL.md` 输出示例 |
| 不做什么 | 舆情监测、竞品分析、退款审批、账号权限处理 | description 末句；目标段边界 |
| 责任落地 | 责任组映射与动词开头的建议动作 | `references/triage-rules.md`；S4 |

## 4 成品目录（最小集 + 一个 references）

```
customer-feedback-triage/
├── SKILL.md                 # 六段正文，约 140 行
└── references/
    └── triage-rules.md      # 六类判据、优先级矩阵、责任组映射，仅 S2–S4 加载
```
