# 召回实测记录（真实模型判断，非词面代理）

本目录记录 skill-creator 的**平台召回实测**结果。这是本地词面代理测试（`check_triggers.py`）无法替代的一环：
代理测试用二元组重合度近似召回，真实召回由模型读 name + description 后决定激活。

## 方法

参照 skill-criticagent 的「有/无行为对比 + description 触发测试」规范：

1. 只向判断者提供 `name` 与 `description` 全文（模拟平台技能目录里的样子），不给技能正文。
2. 对每条 query 独立判断 3 次，判定依据只能是 name + description。
3. 正样本取自需求卡「触发原话」三类（口语 / 术语 / 无术语）；负样本取自「相邻易混淆需求」与无关任务。
4. 判定值只有两个：`skill-creator`（会激活）或 `none`（不激活）。

判断由独立子 agent 执行，每个子 agent 只拿到 name + description 与自己负责的那批 query，
不接触技能正文，也不接触其他 query 的答案。

## 首次实测暴露的测试集错误

第一轮测试把 todo-indexer 的正样本（TODO 相关说法）放进了 skill-creator 的召回测试集，
导致 4 条被正确判为 `none`。这说明两件事：

1. **误判的是测试集，不是 description** —— TODO 索引确实不属于 skill-creator 的职责。
2. **不能拿别的技能的触发语当本技能的负样本期望值** —— 期望值必须按职责边界逐条论证。

第二轮测试集按职责边界重建后，结果全对。

## 与代理测试的差异

| 判据 | 覆盖 | 局限 |
| --- | --- | --- |
| `check_triggers.py` 词面代理 | 结构性漏词（description 缺某类说法） | 不反映模型实际激活行为；对近邻需求易误判 |
| 本目录真实召回实测 | 模型实际激活行为，含误触发 | 判断是自报的，可能与平台实际调度有偏差；不覆盖具体平台的召回算法 |

## 已知边界

1. 真实召回实测的判断由模型自报，不等于平台调度器的实际行为。平台可能用 embedding 相似度而非模型判断，两者会有差异。
2. 本次未测多技能竞争场景：同一目录里若有多个职责相近的技能，误触发风险会上升。本项目当前只有 skill-creator 一个包，未构成竞争。
3. 测试集 17 条覆盖常见说法形态，但无法穷举真实用户表述；新增说法应同步更新本目录并重跑。
