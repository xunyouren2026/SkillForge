# 客户反馈归类

## 一、目标

把一周的客户反馈按问题类型归类，产出 `feedback-triage.md`，含归类维度表、每类判定条件、无法归类处置、输出字段。

1. 每条反馈只归一类；无法归类的进「待确认」区，不硬塞。
2. 输出字段固定：编号、原文、类型、优先级、责任组、建议动作。
3. 事实与建议分列，不替使用者决定是否升级主管。

### 适用范围与边界

- 覆盖：一周内的客户反馈文本，按问题类型归类并排序优先级。
- 不覆盖：舆情监测、竞品分析、退款金额核算、账号权限处理。
- 待确认：跨周合并口径在交付时由使用者确认。

## 二、前置

| 项 | 说明 | 缺失时的处理 |
| --- | --- | --- |
| 反馈原文 | 文本清单，含来源与时间 | 全缺时停止采集，列待确认项，不虚构反馈 |
| 归类维度 | 四类：产品缺陷 / 使用咨询 / 流程投诉 / 商务合作 | 未给时取默认四类，标注「推断」 |
| 责任组映射 | 类型到责任组的对应表 | 未给时按默认映射，标注「推断」 |

运行环境：可读写 Markdown 的编辑器；仅标准库；路径以技能根目录为基准。

## 三、步骤

### S1 收齐与去重

- 输入：反馈原文清单。
- 动作：逐条登记编号与来源；重复文本合并为一条并记合并数。
- 产出：去重后的反馈列表，含编号、原文、来源、时间。
- 失败分支：来源缺失且影响归类时，退回采集补来源；补不到则标「来源缺失」进入待确认区。

### S2 按四类归类

- 输入：去重后的反馈列表。
- 动作：按判定条件逐条归入产品缺陷 / 使用咨询 / 流程投诉 / 商务合作；四条均不满足的进「待确认」区。
- 产出：带类型的反馈列表。
- 失败分支：同一反馈可归两类时，按「产品缺陷优先于流程投诉、流程投诉优先于使用咨询」判定；仍冲突则进待确认区。

### S3 判优先级与责任组

- 输入：带类型的反馈列表。
- 动作：按影响面与紧急度判 P0–P3；按类型映射责任组；写下一条建议动作（动词开头）。
- 产出：含优先级、责任组、建议动作的列表。
- 失败分支：影响面无法判断时标「待确认」，不写 P0；责任组映射缺失时取默认映射并标注。

### S4 生成 feedback-triage.md

- 输入：S3 列表。
- 动作：按固定字段写出归类表、归类维度表、无法归类处置说明、待确认区。
- 产出：`feedback-triage.md`。
- 失败分支：有效反馈为 0 时输出空表并在结论区写明「本周无有效反馈」，不虚构条目。

### S5 自检与交付

- 输入：`feedback-triage.md`。
- 动作：核对六项：字段齐全、每类判定条件可判定、待确认区非空无遗漏、优先级取值合法、责任组映射一致、无占位符残留。
- 产出：自检记录与交付确认。
- 失败分支：任一不符时改完重跑自检，不允许只改人工项。

## 四、输出示例

`feedback-triage.md` 字段：

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 编号 | FB-三位序号 | 是 |
| 原文 | 反馈原句，不改写 | 是 |
| 类型 | 四类之一或「待确认」 | 是 |
| 优先级 | P0–P3 | 是 |
| 责任组 | 默认映射值 | 是 |
| 建议动作 | 动词开头一句话 | 是 |

## 五、禁止项

1. 跳过 S1 去重直接归类。
2. 把无法归类的反馈硬塞进某一类。
3. 改写用户反馈原文。
4. 优先级无依据写 P0。
5. 输出字段增删。

## 六、常见错误

| 症状 | 根因 | 最小修复 |
| --- | --- | --- |
| 类型漂移 | 判定条件未逐条写 | 补四类判定条件 |
| 输出缺字段 | 未对照字段表 | 按字段表补齐并重跑自检 |
| 待确认区为空但存在无法归类条目 | 归类时硬塞 | 回 S2 重判 |
