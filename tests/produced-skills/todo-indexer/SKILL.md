# 代码仓库待办标记索引

## 一、目标

把仓库根目录下所有源码文件中的待办类注释（FIXME / HACK / XXX / BUG / NOTE / TODO）扫描并整理为 Markdown 索引文件 `TODO-INDEX.md`，含文件路径、行号、正文、优先级、类型、提出者六个字段，按优先级降序、同级按文件路径分组。

1. 六种标记（FIXME / HACK / XXX / BUG / NOTE / TODO）全部识别，不可遗漏。
2. 优先级从正文关键字（P0–P3、URGENT、HIGH、LOW）提取；无关键字时默认 P2。
3. 类型分四类（bugfix / refactor / feature / question），按正文关键词判定。

### 适用范围与边界

- 覆盖：仓库根目录及子目录下的源码文件，带 Markdown / txt 等纯文本后缀。
- 不覆盖：二进制、`.lock` 文件、`.git` 与 `node_modules` 目录、issue 自动创建、代码重构。
- 待确认：是否扫描 `.gitmodules` 递归目录（默认否）。

## 二、前置

### 2.1 开工前必须拿到的信息

| 项 | 内容 | 用途 |
| --- | --- | --- |
| 仓库根目录 | 包含 `.git` 的当前工作路径 | 扫描起点 |
| 文件过滤规则 | 后缀白名单 + 排除目录 | 用于 S1 |
| 六种标记词 | FIXME / HACK / XXX / BUG / NOTE / TODO | 用于 S2 匹配 |
| 优先级提取规则 | P0–P3 显式标记 + URGENT/HIGH/LOW 关键词 | 用于 S3 判级 |

缺失处理：仓库根目录以当前工作目录兜底并标注「推断」；文件过滤默认后缀为 `.py .js .ts .tsx .go .rs .java .cpp .c .h .cs .rb .php .swift .kt`，排除 `.git node_modules vendor dist build .next .nuget`；其余为固定规则，不缺。

### 2.2 资源索引

| 文件 | 加载时机 | 作用 |
| --- | --- | --- |
| `scripts/scan_todos.py` | S5 执行 | 标准库扫描脚本，固定实现，不读入上下文 |

运行环境：Python 3.8+，仅标准库；路径一律相对技能根目录。

## 三、步骤

### S1 扫描与文件过滤

- 输入：仓库根目录、后缀白名单、排除目录清单。
- 动作：递归遍历根目录，跳过排除目录内的文件；后缀命中白名单时加入待扫描列表。
- 产出：待扫描文件路径清单（相对仓库根）。
- 失败分支：仓库根目录不存在时退回前置段确认路径；路径不解析时停止执行，列待确认项。

### S2 逐行匹配标记

- 输入：待扫描文件清单、六种标记词。
- 动作：逐文件逐行读取，匹配 `标记词 + 冒号或空格` 正则；命中时记录文件路径、行号、整行正文。
- 产出：原始命中条目列表（含 file / line / body）。
- 失败分支：文件读取编码异常时跳过该文件并在产出末尾附「跳过文件」清单；跳过数超过待扫描总数 20% 时退回前置段确认编码处理口径。

### S3 优先级与类型判定

- 输入：原始命中条目列表。
- 动作：对每条正文扫描 P0–P3 / URGENT / HIGH / LOW 关键字判优先级；扫描 bugfix / refactor / feature / question 关键词判类型；抽取 `@作者` 格式作为提出者，未命中留空。
- 产出：带完整六字段的条目列表。
- 失败分支：同一关键词同时命中多个类型时按 bugfix > refactor > feature > question 的优先级判定；仍冲突时类型留空。

### S4 排序与分组

- 输入：带六字段的条目列表。
- 动作：先按 P0 → P1 → P2 → P3 排序，同优先级再按文件路径分组；组内按行号升序。
- 产出：排序后的最终条目列表。
- 失败分支：条目总数为 0 时输出空文件（只有表头）并在 S5 报告「本次扫描无命中」；不虚构条目。

### S5 执行扫描脚本与写入索引

- 输入：仓库根目录。
- 动作：在仓库根目录执行 `python scripts/scan_todos.py <仓库根目录>`，产出 `TODO-INDEX.md`；核对输出字段齐全。
- 产出：`TODO-INDEX.md`（六字段齐全）。
- 失败分支：脚本退出码非零时读 stderr，定位是路径问题还是文件编码问题；修完后从 S1 重跑。

### S6 自检与交付

- 输入：`TODO-INDEX.md`。
- 动作：核对六项：六字段齐全、优先级在 P0–P3 内、类型在四类内、路径相对仓库根、无占位符残留、跳过文件清单附于末尾。
- 产出：自检记录与交付确认。
- 失败分支：任一不符时改完重跑自检；不允许只改人工项。

## 四、输出示例

### 4.1 产出文件形态

```
仓库根目录/
└── TODO-INDEX.md
```

### 4.2 必含字段

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 文件 | 相对仓库根的文件路径 | 必填 |
| 行号 | 命中行号 | 必填 |
| 正文 | 注释完整内容 | 必填 |
| 优先级 | P0 / P1 / P2 / P3 | 必填 |
| 类型 | bugfix / refactor / feature / question | 选填 |
| 提出者 | `@作者` 形式，未命中留空 | 选填 |

### 4.3 成品片段

```
# TODO-INDEX

## P0 —— 紧急
| 文件 | 行号 | 正文 | 类型 | 提出者 |
| --- | --- | --- | --- | --- |
| src/auth.py | 142 | FIXME: token decode 崩溃，PR#123 blocker | bugfix | @alice |

## P1 —— 高
| 文件 | 行号 | 正文 | 类型 | 提出者 |
| --- | --- | --- | --- | --- |
| src/db.py | 87 | HACK: 临时绕过的索引 bug，上线前必须修 | bugfix | @bob |
```

## 五、禁止项

1. 跳过 S1 文件过滤直接扫描。
2. 正文里改写或截断原始注释内容。
3. 优先级无依据写 P0 或 P1。
4. 二进制文件、`.lock` 文件、`.git` 目录内文件强行扫描。
5. 虚构条目或在无命中时输出假数据。
6. 产出物写绝对路径或 Windows 盘符路径。
7. 输出字段增减。
8. 在非仓库根目录执行脚本。

## 六、常见错误

| 症状 | 根因 | 最小修复 |
| --- | --- | --- |
| 输出条目优先级全是 P2 | 正文不含 P0–P3 / URGENT / HIGH / LOW 关键字 | 检查 S3 判定规则是否加载；给原始命中条目手动标注优先级关键字后重跑 |
| 条目里出现 .git 路径 | 文件过滤的排除目录清单缺失 | 回 S1 补 `.git node_modules` 到排除目录，从 S1 重跑 |
| 输出文件只有表头 | 仓库内确实无六种标记；或后缀白名单未覆盖目标语言 | 先人工 grep 仓库确认；再给后缀白名单补目标后缀后重跑 |
| 同一文件路径反复出现 | 扫描脚本对 symlink 未去重 | 回 S1 给扫描器加 `resolve()` 去重，从 S1 重跑 |
